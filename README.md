# WALL-E and EVE's Signal

An autonomous search-and-resource-planning agent in a partially observable 2D grid world.
WALL-E must find EVE using only noisy signal readings and text clues, while managing a
limited battery and routing to recharge stations when power runs low.

The agent keeps a Bayesian probability grid (NumPy) over EVE's location, updates it from
every observation, and chooses its next action from that belief. Every decision is logged
with human-readable reasoning.

## Project layout

| File | Purpose |
|---|---|
| `config.json` | Mission definition: grid, start, battery, costs, stations, obstacles, sensor model, hidden ground truth |
| `environment.py` | `Environment` class: ground truth, battery accounting, noisy observations |
| `agent.py` | `WallEAgent` class: belief grid, Bayesian/rule-based updates, decision logic |
| `main.py` | Runs the simulation, writes `trace.json`, prints the final mission report |
| `visualizer.py` | Optional: draws the grid, clues, obstacles and WALL-E's path with matplotlib |
| `trace.json` | Output: full action trace of a run (generated by `main.py`) |

## Setup and running

```
pip install numpy          # required (simulation)
pip install matplotlib     # only needed for visualizer.py
```

Run the mission, then (optionally) visualize it:

```
python main.py
python visualizer.py
```

`main.py` options:

| Option | Default | Meaning |
|---|---|---|
| `--config` | `config.json` | Mission file to load |
| `--trace` | `trace.json` | Where to write the action trace |
| `--no-grid` | off | Leave the full belief grids out of the trace (much smaller file) |

`visualizer.py` options: `--config`, `--trace`, `--assets DIR` (folder with optional icon
PNGs), `--out mission_map.png`, `--no-show` (save the image without opening a window).

Icon PNGs are optional. The visualizer looks for `image_6.png` (WALL-E), `image_8.png` (EVE),
`image_9.png` (clue magnifier) and `image_10.png` (obstacle barricade) in `--assets`, next to
the script, and in the current folder. Any missing icon falls back to a plain shape.

## Conventions

- Positions are `[row, col]`. Row 0 is the **north** edge and column 0 is the **west** edge.
- Bearings are in degrees: 0 = east, 90 = north, 180 = west, 270 = south.
- Movement is 4-directional (no diagonals). Obstacle cells cannot be entered.

## Config format (`config.json`)

```json
{
  "seed": 42,
  "grid_size": [10, 10],
  "start_pos": [0, 0],
  "max_steps": 200,
  "battery": {
    "capacity": 100,
    "costs": { "move": 1, "scan": 3, "recharge": 1 },
    "recharge_gain": 40
  },
  "recharge_stations": [[0, 0], [6, 4]],
  "obstacles": [[3, 3], [3, 4]],
  "sensor_model": {
    "signal_decay": 3.0,
    "strength_noise_std": 0.08,
    "direction_noise_std_deg": 25.0,
    "visual_contact_radius": 1.5,
    "clue_scan_radius": 2,
    "clue_reliability": 0.97
  },
  "ground_truth": {
    "eve_pos": [7, 6],
    "clues": [
      { "id": "C1", "pos": [2, 2], "text": "... EVE is located south and east of this spot." }
    ]
  }
}
```

| Field | Meaning |
|---|---|
| `seed` | Seeds the environment's noise generator, so a run is reproducible |
| `grid_size` | `[rows, cols]` |
| `start_pos` | WALL-E's starting cell |
| `max_steps` | Step limit; reaching it ends the run as a timeout |
| `battery.capacity` | Maximum and starting charge |
| `battery.costs` | Charge spent per action (`move`, `scan`, `recharge`) |
| `battery.recharge_gain` | Charge added by one `recharge` action on a station |
| `recharge_stations` | Cells where recharging works |
| `obstacles` | Blocked cells |
| `sensor_model.signal_decay` | Signal strength is `exp(-distance / decay)` plus noise |
| `sensor_model.strength_noise_std` | Std-dev of noise on the strength reading |
| `sensor_model.direction_noise_std_deg` | Std-dev (degrees) of noise on the bearing reading |
| `sensor_model.visual_contact_radius` | Within this distance a scan reports visual contact (noise-free) |
| `sensor_model.clue_scan_radius` | A scan reveals undiscovered clues within this many cells (Chebyshev) |
| `sensor_model.clue_reliability` | How much the agent trusts a text clue (0 to 1) |
| `ground_truth.eve_pos` | EVE's true cell (hidden from the agent) |
| `ground_truth.clues` | Clue id, cell and text (hidden until discovered) |

`ground_truth` is never given to the agent. `Environment.get_public_config()` returns only the
map, battery rules, stations, obstacles and sensor model.

## Environment design (`environment.py`)

```python
env = Environment(config)
obs = env.reset()
obs, reward, done, info = env.step(action, target_pos)
```

**Actions** (every action costs battery):

| Action | `target_pos` | Effect |
|---|---|---|
| `move` | adjacent free cell | Moves WALL-E. Stepping on a clue cell reveals that clue. |
| `scan` | ignored | Returns a noisy signal reading from the current cell and reveals clues within `clue_scan_radius` |
| `recharge` | ignored | Adds `recharge_gain` if standing on a station; otherwise the battery cost is wasted |

An invalid action (blocked cell, non-adjacent target, recharge off-station) still costs
battery and is marked `"valid": false` in the observation.

**Observation** returned by `reset()` and `step()`:

```json
{
  "step": 1, "action": "scan", "valid": true, "message": "Scan complete.",
  "position": [0, 0], "battery": 97,
  "signal": { "strength": 0.03, "direction_deg": 306.0, "visual_contact": false },
  "new_clues": [ { "id": "C1", "pos": [2, 2], "text": "..." } ],
  "found_eve": false
}
```

`signal` is `null` unless the action was a scan. `new_clues` lists only clues discovered by
this action.

**Termination:**

| Status | Condition |
|---|---|
| `eve_found` | WALL-E stands on EVE's cell |
| `battery_depleted` | Battery reaches 0 |
| `timeout` | `max_steps` reached |

**Reward** (for Gym-style use): the negative action cost each step, plus 100 on finding EVE.
The agent does not use it; the decision logic is belief-based.

## Agent design (`agent.py`)

### Belief grid

`belief[r, c]` is the probability that EVE is at cell `(r, c)`. It starts uniform over free
cells and is renormalized after every update.

| Evidence | Update |
|---|---|
| Signal strength | Gaussian likelihood around the expected strength `exp(-d / decay)` for each cell |
| Signal bearing | von Mises likelihood around the bearing from the scan cell to each cell |
| Visual contact | Cells within the contact radius are kept if contact was reported, and heavily down-weighted if not |
| Standing on a cell without finding EVE | That cell's probability is set to 0 |
| Text clue | Rule-based likelihood, see below |

A small likelihood floor stops a single bad reading from permanently eliminating a cell.

### Text clue rules

Clue text is parsed with simple patterns and applied as a soft likelihood weighted by
`clue_reliability`:

| Pattern in the text | Meaning |
|---|---|
| `within N cells` | EVE is within Manhattan distance N of the clue |
| `NOT within N cells` | EVE is outside that zone |
| `north` / `south` / `east` / `west` | EVE lies in that direction from the clue (several words combine) |

Text matching none of these is recorded as evidence but does not change the belief.

### Decision logic (`decide_next_action(obs)`)

Returns `(action, target, reasoning)`. Rules are checked in this order:

1. **Critical battery:** if charge is at most the return cost plus a safety margin (5), go to
   the nearest recharge station, or recharge if already on one.
2. **Top-up:** on a station with battery below 60% of capacity, recharge.
3. **Commit:** if at least 60% of the belief lies within 1 cell of the most likely cell, walk
   there, provided the trip leaves enough battery to return (otherwise recharge first).
4. **Scan:** on an unscanned cell at a scan goal (or at the start), scan, if affordable.
5. **Choose a scan goal:** pick the reachable cell that maximizes belief mass within 2 cells,
   discounted by travel distance, with a small bonus for being far from earlier scans.
   Only goals the agent can reach, scan at, and still return from are considered. The goal is
   re-chosen when a new clue arrives.
6. **Travel:** step along the shortest path (BFS) to the goal, heading to a station instead if
   the next step would leave too little battery to get home.

The tunable constants (`SAFETY_MARGIN`, `RECHARGE_FRAC`, `COMMIT_MASS`) are at the top of
`WallEAgent`.

The agent is given the sensor model (noise levels, decay) through the public config, so its
likelihoods match the simulator. It is not given EVE's position or the clue locations.

## Action trace (`trace.json`)

```
{ "mission", "config", "final_status", "steps": [ ... ] }
```

Each entry in `steps`:

| Field | Content |
|---|---|
| `step` | Step number |
| `decision` | `{action, target}` chosen by the agent |
| `reasoning` | Human-readable explanation, including battery, belief peak and entropy |
| `battery_before`, `battery_after` | Charge around the action |
| `reward` | Reward for this step |
| `observation_in` | The observation the decision was based on |
| `observation_out` | The observation the action produced |
| `belief` | Peak cell and probability, mass within 1 cell, entropy, top 3 cells, and (unless `--no-grid`) the full grid |

The trace is written even if the run crashes partway.

## Final mission report

Printed to the terminal when the run ends:

- Outcome (EVE found, battery died, or timeout) and total steps
- Battery remaining and number of scans
- Evidence found: each discovered clue with what it implied, plus the strongest signal reading
- Inferred location, with confidence as the probability of the exact cell and of "within 1 cell"
- Ground truth for evaluation (this line is for checking the agent, not something it knew)
- Recommended next action

Example (default config):

```
Outcome            : SUCCESS - WALL-E reached EVE
Total steps        : 14
Battery remaining  : 84/100
Scans performed    : 1

Evidence found:
  - C1 at (2, 2): "A fresh trail of crushed plant debris: EVE is located south and east of this spot."
      => inferred: EVE lies east and south of (2, 2)
  - Strongest signal: 0.03 at (0, 0) (bearing 306 deg, south-east)

Inferred location  : (7, 6)
Confidence         : 100.0% exact cell  |  100.0% within 1 cell
Ground truth (eval): EVE at (7, 6)  -> CORRECT
```

In the default mission, clue C1 and one scan are enough to narrow the search a lot. To see
more scanning and recharging, move `eve_pos` (for example to `[0, 9]`) or lower
`battery.capacity`.

## Visualization

`visualizer.py` loads `config.json` and `trace.json` and draws a 10x10 grid with WALL-E's start
cell, EVE's true position, all clue cells (faded if never discovered), obstacles, recharge
stations, and WALL-E's path as a red-orange line with arrows. It saves `mission_map.png`.

## Testing notes

The agent was run across many EVE positions and noise seeds, and with reduced battery
capacities (25 to 40) that force recharging. EVE was found in every run, with no invalid
actions. These were ad-hoc checks, not a packaged test suite.

## Known limitations

- Scanning always happens at WALL-E's current cell; there is one kind of scan.
- Clue text is understood only through the patterns listed above.
- The config is JSON only. There is no initial signal reading or timestamp in it, and the only
  time limit is `max_steps`.
- EVE counts as found only when WALL-E walks onto her cell; visual contact alone does not end
  the run.
- There are no decoy signals, multiple agents or physics simulation.
